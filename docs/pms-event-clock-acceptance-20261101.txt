Findings and fixes
1. Reservation history sliced raw UTC strings; security/system/entity/KVKK
   audit screens used the browser timezone. A common event parser now treats
   legacy suffixless API datetimes as UTC and renders Europe/Istanbul once.
   Explicit offsets are respected. The display zone is labelled. Calendar-only
   business/stay/service dates are not converted into fabricated instants.
   Cashier public helper defaults remain backward-compatible.
2. A rejected checkout pre-posted the unposted room remainder. The following
   night audit could then post the same night again. Both service paths now
   evaluate the durable planned balance and business-date/override guards
   before materializing the room remainder. Approved prepaid checkout still
   completes revenue; a denied attempt does not create that room charge.
3. A duplicate payment reference hit its unique index as an unhandled 500.
   The index remains enforced; the API returns 409 before balance/cashier
   mutations. A same-key idempotent replay still returns the original payment.
4. Night-audit preview used UTC calendar date while normal run guards used
   Türkiye date. Preview now agrees after hotel midnight without shifting the
   authoritative operating day. Financial summary selects the latest tenant/
   day run, not an earlier superseded dry run.
5. System-log CSV retains the raw source timestamp AND labelled display time,
   escapes fields, prevents spreadsheet formula execution, and disables export
   after load failure. Late older responses cannot replace a newer refresh.
